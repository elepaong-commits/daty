# daty

[한국어](README.md) · **日本語**

カップルで一緒に使うデート記録のWebアプリです。行きたい場所と行った場所を地図に集め、予定と記録をカレンダーに残し、その日の写真や動画をアルバムにまとめます。実際にデプロイして運用しているサービスです。

## 主な機能

- **地図 / ジャーナル:** Googleの場所検索でスポットを保存し、行きたい場所と行った場所をピンで表示します。スポットごとにメモ、評価、訪問記録、そこで撮ったアルバムをまとめて見られます
- **カレンダー:** 予定(PLAN)と記録(RECORD)を日付ごとに残します。1日の記録を時間順につないで「デートコース」として表示し、記念日(100日ごと・毎年)を自動で表示します
- **アルバム:** 1日、旅行の期間、月単位で写真・動画をまとめます。ベストショット(表紙)、キャプション、並べ替え、別のアルバムへの移動、一括保存に対応しています
- **ふたりで使う:** 写真やメモに絵文字のリアクションとコメントを残せます。パートナーが新しい予定や写真を追加するとWebプッシュで通知し、朝には記念日・今日の予定・「N年前の今日」をお知らせします
- **年末まとめ:** 1年間に行った場所、エリア、写真の数をまとめて振り返ります
- **韓国語 / 日本語:** 画面の文言はすべて2言語に対応し、スポット名はその国の言葉で保存します
- **2つのデザイン:** 標準デザインとドット(ピクセル)デザインを端末ごとに選べ、それぞれライトモード・ダークモードに対応しています
- **オフライン閲覧:** Service Workerがアプリ本体・最近のデータ・サムネイルをキャッシュするので、接続が切れても記録を見られます

## 設計で工夫した点

- **メモリ1GBのサーバーに合わせた設計:** 写真・動画はサーバーを経由せず、ブラウザがpresigned URLでR2に直接アップロードします。サーバーはR2にHEADを送ってサイズと形式だけを確認してから記録します。署名にはAWS SDKの代わりに軽量な `aws4fetch` を使い、通知や後片付けの処理も別プロセスを立てずにAPIプロセス内のタイマーで動かしています
- **ブラウザ側での前処理:** アップロード前に写真を縮小し、サムネイルを作り、EXIFの撮影日時を読み取ります。ファイルのフィンガープリント(SHA-256)で同じ写真の二重アップロードを防ぎ、途中で切れてもアップロード済みの分は残るよう1枚ずつ登録します
- **画像キャッシュ:** 写真の署名付きURLの署名時刻を6日単位で固定し、URLが変わらずブラウザキャッシュがそのまま効くようにしています
- **カップル単位のデータ分離:** すべてのデータはカップルIDで所有され、すべてのクエリはログイン中のユーザーのカップルに範囲を限定します。他のカップルのIDでアクセスするケースはテストで確認しています
- **アクセシビリティ:** モーダルのフォーカス制御、キーボードフォーカスの表示、44pxのタップ領域、テキストのコントラスト基準を守っています

## セキュリティ

- パスワードはscryptでハッシュ化し、セッションはhttpOnly・SameSite=LaxのCookie(HS256 JWT)で管理します。パスワードを変更すると他の端末のセッションはすぐに無効になります
- ログイン、パスワード再設定、招待コード入力などはIPごとに試行回数を制限しています。ハッシュ計算も同時に数件だけ実行するようにし、リクエストが集中してもサーバーのメモリが尽きないようにしています
- 新規登録はデフォルトで閉じています。リクエストボディはすべてZodで検証し、ユーザーが保存するリンクは `http(s)` のみ受け付けます
- R2バケットは非公開で、アップロードキーの形式はサーバーで検査します。DBのバックアップは書き込み権限を分けた別のバケットに保存します
- 秘密情報(APIキー、DBのURL、セッションキー)はリポジトリに含まれていません。必要なキーの一覧は `.env.example` にあります

## ローカルでの実行

Node.js 22とDockerが必要です。

```bash
# backend (http://127.0.0.1:4000)
cd backend
npm install
cp .env.example .env       # 初期値はローカル開発用DB。SESSION_SECRETは openssl rand -base64 48 の結果に置き換える
npm run db:up              # 開発用PostgreSQL (Docker, localhost:5433)
npm run db:migrate:deploy  # マイグレーションを適用
npx prisma db seed         # サンプルデータと開発用アカウント dev-a@daty.local / daty1234
npm run dev
```

```bash
# frontend (http://localhost:5173)
cd frontend
npm install
cp .env.example .env.local  # Google MapsのAPIキーとマップID
npm run dev
```

R2、メール(Resend)、Webプッシュのキーは空のままでも、その機能だけがオフの状態で起動します。

テスト:

```bash
cd backend && npm test             # 専用のDB daty_test を作成して使う
cd frontend && npm run lint && npm test
```
